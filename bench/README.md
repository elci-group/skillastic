# skillastic bench

Measures how coding agents perform when their project skill docs have
drifted from the app they describe — and how much skillastic's migrated
skill docs close the gap. Built for **tool-use accuracy and efficiency**
metrics, not just pass/fail.

## Design

Each agent solves 4 tasks under 2 arms:

- **stale** — the workspace's `SKILL.md` documents the app at v1 (wrong
  conventions for the v2 code in front of the agent).
- **migrated** — same workspace, but `SKILL.md` is the v1 doc plus real
  migration notes generated by `skillastic migrate` (dogfooded by
  `build_skills.py` against a synthetic v1→v2 git history with a
  conventional breaking-change commit).

Agents may run the shipped tests but must not modify them. Every run
produces a JSONL record (`runs.jsonl`) with:

- correctness: `tests_passed/tests_total` from the fixture's `grader.py`
- convention adherence: per-fixture regex checks (`checks.json`) —
  uses-current-API vs uses-stale-API vs reinvented-logic
- tool-use accuracy: `tool_calls_total` / `tool_calls` by tool,
  `tool_errors`, `forbidden_edits` (modified test files)
- efficiency: `duration_s`, `tokens_in`/`tokens_out` (where the harness
  exposes them)

## Tasks (`fixtures/`)

| task | drift |
|---|---|
| `canon-api` | v1 `api.query()` raw dicts → v2 `Client`/`Row` with canonicalization (NFC, zero-width strip, casefold) |
| `dep-swap` | v1 `textutil.pad()` naive width → v2 `fmt.align()` display width (combining marks) |
| `flags-cli` | v1 CLI flags `--out`/`--fast` → v2 `--output-dir`/`--mode fast` |
| `state-format` | v1 `settings.ini` (stale values) → v2 nested `settings.json` |

## Agents

| name | harness | model |
|---|---|---|
| `kimi-k3` | kimi CLI (`-p --output-format stream-json`) | `kimi-code/k3` |
| `kimi-k2.7` | kimi CLI | `kimi-code/kimi-for-coding` |
| `codex` | `codex exec --json` | codex default |
| `agy` | `agy -p` (traces from conversation sqlite) | agy default |
| `groq-gpt-oss-120b` | `groq_harness.py` (raw tool loop) | `openai/gpt-oss-120b` |
| `groq-llama-70b` | `groq_harness.py` | `llama-3.3-70b-versatile` |

Groq models run through `groq_harness.py` (a minimal sequential tool
loop, `parallel_tool_calls=false`) because both CLI harnesses are
provider-incompatible: kimi-code echoes `reasoning_content` that Groq
rejects on follow-up turns, and codex 0.144+ only speaks the Responses
API, which Groq rejects. Known Groq exclusions: `qwen/qwen3-32b` (404 on
this account) and `groq/compound` (no tool calling support).

kimi runs need an isolated home at `/tmp/kbench-home` (copy of
`~/.kimi-code/config.toml` without a global thinking `effort`, with
`credentials`, `oauth`, `device_id` symlinked) — Groq rejects the global
`effort = "max"` setting.

## Usage

```sh
python3 bench/build_skills.py            # regenerate skill_migrated.md (idempotent)
python3 bench/run.py --list              # show the matrix
python3 bench/run.py --workers 4         # full matrix -> bench/results/<ts>/
python3 bench/score.py bench/results/<ts>  # aggregate -> report.md + results.csv
```

Useful flags: `--agents`, `--tasks`, `--arms`, `--timeout`, `--out`.
`results/` is gitignored.
